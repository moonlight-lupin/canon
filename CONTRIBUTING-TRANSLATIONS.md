# Translating Canon

Canon is used by churches that worship in many languages. You can add yours, or improve one, **without writing any code**: each language is one folder of plain text files. This guide is for translators. Developers should also see [CONTRIBUTING.md](CONTRIBUTING.md).

## What can be translated

Canon has two kinds of language:

- **The service's languages.** These are what the congregation reads: the bulletin, the slides, the share pages and the e-mails to the team. A church picks them in Settings → Languages. Canon already prints services in many languages. Your translation adds the small fixed words around the content, such as "Order of Service", "Leader / People" and "Refrain".
- **Canon's own screens.** These are the menus, buttons and help text the church's staff use. A language that has a screen translation gets a **UI** badge in Settings → Languages, with how complete it is (for example "UI 82%"). Staff can then choose it as their language.

You can do either, or both. Even a few files help.

## The files

Everything for a language lives in `locales/<code>/`. `<code>` is the language's code from [shared/languages.ts](shared/languages.ts): `ms` Malay, `id` Indonesian, `ta` Tamil, `ko` Korean, `ja` Japanese, `es` Spanish, `tl` Tagalog, `vi` Vietnamese, and so on.

| File | What it covers | Size |
|---|---|---|
| `outputs.json` | Words printed in bulletins, slides and exports: "Order of Service", "Leader", "People", "Refrain", "All stand", the liturgical seasons, the closing slide | about 35 phrases. **Start here.** |
| `server.json` | E-mails (serving reminders, library reminders) and public pages (the visitor welcome form, the page for connecting an AI app) | about 90 phrases |
| `ui.json` | Canon's screens | about 2,300 phrases. Partial is fine. |
| `meta.json` (optional) | `{ "fallback": "id" }`: a language to use for phrases yours doesn't have yet, before English | — |
| `docs/guide/<code>.md` (optional) | The user guide shown inside Canon (Help → Guide) | a long document |

Each `.json` file maps **the English text** to **your translation**:

```json
{
  "Order of Service": "Aturan Ibadah",
  "Refrain": "Korus",
  "Serving on {d} {mon}": "Bertugas pada {d} {mon}"
}
```

The English lists to translate from are:
- `locales/en/outputs.json` for printed words;
- `locales/en/ui.json` for the screens, every phrase, generated by `npm run i18n`;
- the English keys in `locales/zh/server.json` for e-mails and public pages.

Only include what you have translated. Anything missing shows in English (or your `fallback` language), so a half-done file is safe to share.

### Rules for a phrase

- **Keep the placeholders** in curly braces exactly: `{n}`, `{name}`, `{date}`, `{cur}`. They are filled in by Canon. You may move them, e.g. `"{n} open roles"` → `"{n} 个岗位待排"`.
  - Dates are the one exception. `"Serving on {d} {mon}"` may use `{d}` (day), `{m}` (month number) and `{mon}` (short month name) in any order. Chinese uses `"{m}月{d}日 服事人员"`.
- **Keep the meaning, not the words.** Write what a church member in your language would naturally say. Use your church tradition's usual terms for worship words, such as liturgist, benediction and refrain.
- **Keep it short** where the English is short: buttons and slide labels have little room.
- **A key with "‖" has a context.** `"Fund‖books"` is the English "Fund" as used in book-keeping. The plain `"Fund"` is the same word on the offering screens. Translate each for its place: Chinese uses 款项 in the books and 奉献项目 for offerings. English shows only the part before "‖".
- Plain text only: no HTML. Line breaks as `\n`.

## Step by step

You need [Node.js 24](https://nodejs.org) and a copy of Canon (`git clone`, then `npm install`).

1. **Start the language:**
   ```bash
   npm run i18n:new ms
   ```
   This creates `locales/ms/ui.json`. Create `outputs.json` and `server.json` beside it the same way, as `{}` to start.
2. **Translate.** Open the files in any text editor (save as UTF-8) and add phrases from the English lists.
3. **Check:**
   ```bash
   npm run i18n:check ms
   ```
   It lists what is still to translate, phrases that are no longer used, and any placeholder that doesn't match. A placeholder mistake makes it fail; the others are just information.
4. **Update the generated files:**
   ```bash
   npm run i18n
   ```
   This refreshes the list of languages and how complete each is. Then run `npm test`.
5. **See it:** `npm run dev`, open Canon, choose your language in the sidebar (or Settings → My profile), and check the screens, a bulletin and the slides.
6. **Send it:** open a pull request with your `locales/<code>/` folder (and `docs/guide/<code>.md` if you translated the guide), plus the files `npm run i18n` changed. Say who reviewed the wording, if anyone.

If you're not comfortable with git, open an issue and attach the files. A maintainer will add them.

## Chinese: Simplified and Traditional

Simplified (`zh`) and Traditional (`zh-Hant`) Chinese are kept in step automatically by `npm run i18n`, phrase by phrase and both ways:
- edit either `locales/zh/*.json` or `locales/zh-Hant/*.json`, and the other is converted to match (OpenCC, Taiwan phrasing);
- a phrase you have written by hand in both scripts, for example a word Taiwan says differently, is kept as you wrote it;
- the user guide works the same way between `docs/guide/zh.md` and `docs/guide/zh-Hant.md`, as whole files.

The same conversion applies to a church's own content: hymn words, titles, the visitor form's wording and so on. A church that types Chinese once gets both scripts, on screen and in print.

## What isn't translatable yet

- The **CSV import and export** messages (Settings → Import CSV) are in English and Chinese only. They are built in code from pieces of text.
- **Error messages from the server** that aren't listed above show in English.
- The **church's own content** (hymns, readings, templates) is entered by each church in its languages. It isn't part of these files.
